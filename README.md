# Log Challenge

A static, GitHub-Pages-hostable support-engineer debugging exercise: a Datadog-style Lucene log search UI plus a read-only SQL database browser, both running entirely client-side against a SQLite file.

The app has three tabs: **Challenge** (the brief — send candidates to `index.html`, they land here), **Log Explorer**, and **Database Admin**.

The answer key lives at [`answers.html`](answers.html) — a separate page that **nothing in the app links to**. Don't add a link to it from `index.html`/`js/*` and don't share that URL with whoever is taking the challenge. It's committed (so it travels with the repo and stays in sync with the generated data) but kept out of the candidate-facing surface — it's `noindex`'d and reachable only if you type the path.

## How it works

- **Data**: `data.db` is a plain SQLite database with four tables — `users`, `accounts`, `transactions`, `logs` — generated by [`data/build_db.py`](data/build_db.py) (stdlib-only Python, deterministic seed). It also embeds several deliberate "incidents" that the tickets in the Challenge tab (`js/challenge.js`) are built around (declined charge, duplicate charge, account lockout, an unhandled-exception stack trace, a "silent failure" with no error log, and a systemic outage window).
- **Runtime**: the browser loads `data.db` with [sql.js](https://sql.js.org/) (SQLite compiled to WebAssembly, vendored in `vendor/`) and runs actual SQL against it in memory — nothing is written back, and the connection is opened with `PRAGMA query_only = ON` as a second line of defense on top of the UI's statement allowlist.
- **Challenge** (`js/challenge.js`): the ticket brief, rendered in-app — static content, no DB dependency.
- **Log Explorer** (`js/logs.js` + `js/lucene.js`): a hand-rolled Lucene/Datadog-style query parser (`field:value`, quoted phrases, wildcards, `AND`/`OR`/`NOT`, parentheses, numeric ranges/comparisons) filters the `logs` table client-side, plus a facet sidebar (service, level, time range) and a detail panel with clickable IDs that jump to the matching row in Database Admin or re-scope the search to a `trace_id`.
- **Database Admin** (`js/dbadmin.js`): table/schema browser and a SQL box restricted to `SELECT` / `WITH` / `EXPLAIN`.

No backend, no build step — just static files.

## Running locally

```sh
python3 -m http.server 8000
# open http://localhost:8000/
```

## Regenerating the database

```sh
python3 data/build_db.py          # writes data.db
```

Re-running is deterministic (fixed random seed), so the ticket text in `js/challenge.js` and the walkthroughs in `answers.html` (usernames, merchants, IDs, approximate dates) stay valid as long as the generator itself isn't edited. If you do edit it, double-check those two files still match — nothing enforces that automatically.

## Deploying to GitHub Pages

Push this directory to a repo and enable Pages for the root of the default branch (Settings → Pages → Deploy from a branch). No build step is required — `index.html` is the entry point.

Since GitHub Pages serves everything in the repo, `answers.html` will be publicly *reachable* at `<your-pages-url>/answers.html` even though nothing links to it — that's obscurity, not access control. If you want a harder guarantee that the candidate can't stumble onto it, keep it in a private repo, or ask for a stricter gate (e.g. a passphrase check) before pushing.

## Project structure

```
index.html                app shell, tab layout (Challenge / Log Explorer / Database Admin)
answers.html               private answer key — unlinked from the app, don't share
css/style.css               app styling
css/answers.css             answers.html-only styling
js/util.js                   small DOM/formatting helpers
js/db.js                     sql.js bootstrap + query helpers
js/lucene.js                 Lucene-style query parser/evaluator
js/challenge.js               Challenge tab (ticket brief)
js/logs.js                    Log Explorer tab
js/dbadmin.js                 Database Admin tab
vendor/sql-wasm.{js,wasm}    sql.js (vendored, MIT licensed)
data/build_db.py             mock data generator
data.db                       generated SQLite database (committed)
```
